# PastForward: project overview

Read this first. It explains what PastForward is, where it stands today, and where it is heading. The infrastructure tasks are in **SETUP-BRIEF.md** (section 1) and **SETUP-UPDATE.md** (which replaces its sections 2 and 3).

## The idea

History rhymes. PastForward pairs an event from history with a recent event that follows the same pattern, then counts the same number of years forward to imagine when it may return.

> 1918 Spanish flu → 102 years → 2020 COVID-19 → 102 years → around 2122, the next pandemic?

The goal is a moment of recognition: "I know that event from history, I lived through this one, I see the connection, so what might come next?" It should feel like a beautifully made tool, a bit magical, and never like a chatbot or a newspaper. The future dates are presented as a way to imagine, not as forecasts.

- **Owner:** Elad, the product owner and the one who makes decisions.
- **Name and domain:** PastForward, **pastforward.app** (registered at Porkbun).
- **Audience:** curious general adults, mostly on phones. Everything is designed mobile-first and fits on one screen.

## What exists today (working prototype)

- **Timeline:** one swipeable river of time from 1750 to 2300, about 50 years per screen. The event in the middle snaps into focus, and labels like "100 years ago", "Today" and "In 50 years" give orientation.
- **Then → Today → Next:** a three-step strip plus a big "Jump to 2020 →" button. The timeline travels the gap with a year counter.
- **Dive deeper:** a full-screen view for each event with three parts:
  - **Story:** the facts.
  - **The chain:** every known real occurrence of the pattern, with the years between them.
  - **World in [year]:** a dot-matrix world map with a short headline for each region, showing what else was happening that year.
- **Your future:** enter a birth year to see which echoes fall within that lifetime and at what age. It produces a shareable story-size image card. The birth year stays on the device.
- **Share a rhyme:** turns any rhyme into a vertical image card with a link.
- **Daily puzzle, "Find the echo":** three rounds, the same for everyone each day (day numbering starts at 1 on 21 October 2026, UTC). It has a score, a streak and an emoji share result.
- **Voting, "Does this rhyme?":** results show only after you vote. Rhymes can be ranked by Most convincing and Most debated. It needs the database to go live.
- **Content:**
  - 48 rhymes, from the Lisbon earthquake of 1755 to the Iberian blackout of 2025.
  - 155 additional real echoes.
  - World snapshots for 61 years across 8 regions, each with a short headline.
  - Facts were researched and checked, and political topics are worded neutrally.

**Technical shape:** a single static `index.html` of about 370 KB. It has no framework and no build step on the server, and all content is embedded. It uses Google Fonts and draws everything on HTML canvas. The repository is **eladhackim/pastforward** (branch `main`). The site file is generated by Claude from source files (templates, data and a build script), so do not hand-edit `index.html`; changes would be overwritten.

## Where we are heading

**Next: launch infrastructure, all on Cloudflare** (your part: SETUP-BRIEF.md section 1, then SETUP-UPDATE.md):

```
GitHub repo (site + functions/) ── push ──► Cloudflare Pages · pastforward.app
                                              ├ static site (index.html), later share pages + preview images
                                              ├ Pages Functions: /api/scores · /api/vote · /api/puzzle (edge-cached 60 s)
                                              │        └──► D1 database "pastforward" (votes, puzzle results)
                                              └ Web Analytics (free, cookie-free)
```

- **One provider, one dashboard, €0/month to start.** The likely first cost is Cloudflare's paid Workers plan ($5/month) if the API passes about 100,000 requests a day.
- **D1 (SQLite)** holds two small tables. The API accepts writes only from our own site and caches the totals at the edge.
- **Web Analytics** shows visits, referrers and countries. A product-analytics tool such as PostHog may be added later, once there is enough traffic to study shares and puzzle retention.

**Then Claude builds:**
1. A share page per rhyme (for example `pastforward.app/r/flu`) with its own preview image, so links show the rhyme card in WhatsApp, X and iMessage.
2. Analytics for key actions (later, if Web Analytics is not enough):
   - rhyme opened
   - jump
   - dive deeper
   - world map opened
   - rhyme shared
   - future used
   - future shared
   - puzzle started
   - puzzle finished, with the score
   - vote
3. Cloudflare Turnstile against vote-stuffing.
4. An installable home-screen app (PWA), with the content moved out of the code into a data file.
5. Moving the source files and build script into the repository, so the site can always be rebuilt.

**Later, possible ways to earn money:**
- printed "Your life, played forward" posters as gifts
- a small paid tier (for example family timelines and extra rhymes), sold through Lemon Squeezy or Paddle, which handle EU VAT
- a daily puzzle email with one sponsor slot

No ads.

## Principles to respect

- **Simple and light.** Static first. Add a service only when it clearly earns its place.
- **Privacy by default.** The site collects no personal data: a random device ID is used only to prevent double votes, the birth year never leaves the device, and analytics use no cookies.
- **No secrets in the site.** The API runs on Cloudflare with a database binding, so no keys are embedded in the page. Passwords and recovery codes are never shared or committed.
- **Free plans first.** Upgrade only when traffic requires it.
- **Keep the site's behaviour unchanged** while doing infrastructure work.
